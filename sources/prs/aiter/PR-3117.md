## Summary

Adds a new FlyDSL MXFP4 x MXFP4 stage-2 fused-MoE variant `_t64x128x256_atomic_persist_async_w4_cumul3` tuned for DeepSeek-R1 / V3 EP4 prefill on CDNA 4. The kernel introduces an async X DMA prologue, a cu_num_mul=3 persistent expansion, an asymmetric b_lo / b_hi 3:1 split, LDS-staged sorted_weights, `disable_xdl_arb_stall` + `s_setprio(1)`, and a "scales-before-B" K-loop ordering.

## Why It Matters

The PR adds this stage-2 path as a production fp4×fp4 variant for DeepSeek-R1 / V3 EP4 prefill in AITER (the PR body does not establish it as a default or AITER-wide recommendation). **It was reverted the next day by [PR #3344](https://github.com/ROCm/aiter/pull/3344) (merged 2026-05-26), so it does not currently ship — treat it as a worked technique example.** Measured on MI355X (PR body, 3 reps): end-to-end `fused_moe` **3711.8 → 3384.9 µs, −8.81%**, 12/12 correctness. Two of the stacked changes are independent: (1) the **async X DMA prologue** overlaps prologue VMEM with the K-loop, and (2) **dropping a redundant `out.fill_(0)`** from the stage-2 wrapper — the `fused_moe` path already zeros `moe_buf` — saves an estimated ~130 µs per call of redundant HBM writes (a PR-side estimate, not separately measured; "~130us of HBM bandwidth" in the PR text is loose wording for time). It is also a worked FlyDSL example combining persistent scheduling, xcd-aware tile expansion, scheduler-barrier ordering, and wave-priority tuning.
